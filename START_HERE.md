# LogicFlow CSV review assistance pack

## Status — 9 November 2026

These are enriched REVIEW INPUTS, not completed or independently validated research data. No human component ratings, same-control links, adjudication decisions or experimental outcomes have been invented. The analysis/evaluation commands will continue to reject incomplete reviews. That is expected.

## Files and changes

- coder_A.csv and coder_B.csv: 190 original sampled answers each. Original question, answer, IDs, phase and blank rating fields are preserved. Organisation/country/period/date, review role and instructions are added. Neither sheet contains automated ratings or highlighted candidate quotations. Two different researchers must code these independently.
- adjudicated_sample.csv: the same 190 sampled answers and original blank decision fields, with metadata and instructions. Complete only after independent coding; explain every final decision.
- chain_units.csv: 212 DRAFT report-stage TASKS, not 212 identified governance controls. Draft IDs only identify tasks. Each has reviewed=0; actual control IDs, scores, evidence IDs and quotations are blank. Replace each draft task with the control(s) found in that report-stage. Assign final unique unit IDs. A stage can have several controls; do not collapse them into one just to preserve the draft row count.
- coverage.csv: 212 original report-stage records. Organisation metadata and source-search counts are added; review_complete=0. Applicability and full-scope review decisions remain pending.
- source_context.csv: all 2,788 substantive eligible answers from the study_run3 corpus, with source IDs and report metadata. It is a reference copy under a NEW filename, not a replacement for any frozen corpus file.
- automated_evidence_suggestions.csv: 858 candidate excerpts generated by the existing original-rule regular expressions and question-based lifecycle mapping. Every excerpt is copied verbatim from its identified source answer. These are search aids, not component scores, confirmed links, or complete evidence. They do not detect all negation, prospective claims or semantic relationships. Zero matches never establish absent disclosure.
- CODEBOOK.md: unchanged copy of the supplied codebook.

The source context came from the previously reviewed GitHub commit db9e2d2b5d38d69b9da49491e77d6a978c659701. All 190 uploaded sampled answers were matched exactly to that corpus by answer text, question and source/report IDs before enrichment. Report-stage coverage was also matched to that corpus. Use the pack with that frozen sample, not a different run with different sampling membership.

## Work sequence

1. Back up the current five review CSVs in your actual frozen workspace before replacing them. Copy only the five same-name review CSVs from this pack. Do not replace frozen.json, eligibility.csv, eligible_answers.csv, eligible_reports.csv, frozen_sample.csv, source code or rule files with this pack.
2. Give one blinded coder sheet and CODEBOOK.md to each researcher. Keep automated_evidence_suggestions.csv and the other researcher's ratings away from the independent sample coding process. Both coders should assess the complete answer text, following the codebook; do not manufacture disagreement or agreement.
3. Review every sampled answer independently, recording four component scores 0-3, three explicit link scores 0/1, exact quotations where supported and notes. A no-evidence score is a finding about the reviewed disclosure, not absence of internal practice.
4. Compare the recorded independent decisions and complete adjudicated_sample.csv, keeping both originals intact. Adjudication is not copying an automated baseline or silently averaging ratings.
5. For full-report main coding, filter source_context.csv by each report_id and read ALL answers. Stage hints are incomplete search aids. Identify actual controls; add or remove draft task rows as appropriate. Review all four stages for each included report and complete coverage.csv.
6. A genuinely applicable stage with no disclosed control requires the codebook's reviewed zero placeholder only AFTER a complete documented search. An inapplicable stage has no chain-unit rows and a justified coverage decision. Missing data alone cannot determine applicability.
7. For a score of 3, record a specific artifact/reference/date and verify the evidence. Public URLs require an accessibility check and date. Document independent review/adjudication of main control coding too; sampled answer agreement alone does not validate every control judgment.
8. Complete genuine human reviews before running evaluate/analyse. Do not set reviewed or review_complete to 1 merely to pass validation.

Component scores: 0 no supporting disclosure in the reviewed scope; 1 generic mention; 2 concrete mechanism; 3 traceable mechanism. A substantive complete chain requires all four components >=2 AND all three explicit same-control links=1. Co-occurrence is insufficient.

## Execution after completion

From your project folder, using the actual frozen workspace name:

```powershell
python implementation.py status --workspace study_run3
python implementation.py evaluate --workspace study_run3
python implementation.py analyse --workspace study_run3
```

Status reports blank fields; it cannot certify review quality or independence. Extra metadata columns are ignored by the currently reviewed implementation. Draft tasks deliberately fail completion checks until replaced with genuine reviews.
